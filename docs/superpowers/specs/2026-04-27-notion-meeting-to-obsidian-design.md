# Notion Meeting AI to Obsidian Design

## Goal

Build a local tool that syncs meeting notes generated by Notion Meeting AI through the official Notion API, converts them to Obsidian-friendly Markdown, and lets the user review or edit notes through both a CLI and a local Angular frontend.

## Decisions

- Use the official Notion API.
- Read secrets and local paths from environment variables.
- Use Python for the sync engine, CLI, and local FastAPI backend.
- Use Angular for the frontend. Do not use React.
- Keep the first version local-only.
- Store generated notes in the Obsidian vault path provided by `OBSIDIAN_VAULT_PATH`.

## Environment

Required:

```txt
NOTION_TOKEN=
NOTION_SOURCE_ID=
OBSIDIAN_VAULT_PATH=
```

Optional:

```txt
OBSIDIAN_MEETINGS_FOLDER=Meetings
SYNC_STATE_PATH=
```

## Architecture

The repository is a monorepo with a Python backend and an Angular frontend.

- `backend/src/notion_meeting_to_obsidian/config.py` reads and validates environment configuration.
- `backend/src/notion_meeting_to_obsidian/notion.py` talks to the Notion API.
- `backend/src/notion_meeting_to_obsidian/converter.py` converts Notion page metadata and blocks to Markdown.
- `backend/src/notion_meeting_to_obsidian/writer.py` writes safe `.md` files into the Obsidian vault.
- `backend/src/notion_meeting_to_obsidian/state.py` stores incremental sync state.
- `backend/src/notion_meeting_to_obsidian/sync.py` orchestrates Notion fetch, conversion, writing, and state updates.
- `backend/src/notion_meeting_to_obsidian/api.py` exposes local FastAPI endpoints for the Angular app.
- `backend/src/notion_meeting_to_obsidian/cli.py` exposes `sync` and `serve` commands.
- `frontend/` contains the Angular editor UI.

## Data Flow

1. The CLI or Angular app requests a sync.
2. The backend queries `NOTION_SOURCE_ID` using `NOTION_TOKEN`.
3. The backend compares each Notion page `last_edited_time` against local state.
4. New or changed pages are fetched with their block children.
5. Blocks are converted to Markdown with YAML frontmatter.
6. Markdown files are written under `OBSIDIAN_VAULT_PATH/OBSIDIAN_MEETINGS_FOLDER`.
7. The Angular app can preview generated Markdown, save reviewed drafts, and edit existing synced files.

## Markdown Format

Generated notes include YAML frontmatter:

```yaml
---
title: "Meeting title"
notion_id: "page-id"
notion_url: "https://notion.so/..."
last_edited_time: "2026-04-27T10:00:00.000Z"
synced_at: "2026-04-27T12:00:00Z"
---
```

The body uses standard Markdown headings, lists, tasks, quotes, code fences, dividers, and links where Notion blocks provide enough information.

## Frontend

The Angular app is an operational editing surface, not a landing page. It shows:

- A sidebar/list of synced meetings and vault notes.
- A sync action with status feedback.
- A Markdown editor.
- A rendered preview pane.
- Save actions for reviewed drafts and existing Obsidian files.

The visual direction is calm, dense, and work-focused: restrained colors, clear hierarchy, minimal chrome, and no decorative dashboard card grid.

## Error Handling

- Missing environment variables produce explicit configuration errors.
- Notion API errors stop the current operation without deleting existing notes.
- Page-level failures are surfaced to the caller and kept out of state updates.
- File writes create parent directories and use safe filenames.
- The API returns structured error responses for UI display.

## Testing

Backend unit tests cover:

- Rich text and block conversion.
- Markdown frontmatter generation.
- Safe filename generation.
- Incremental sync state behavior.

API and frontend integration can be expanded after the first local workflow is validated.
